# 改善実装計画：ボタン重なり解消・歌詞一発取得・アーティスト人気曲20曲表示

ユーザー様からのご回答とご要望に基づき、3点の改修を実施します。

## ユーザー確認事項
- **アーティスト人気曲の展開**: 「Top Songs ＞」を押すたびに 5曲 ⇄ 20曲 がトグル切り替え（展開/折りたたみ）されます。
- **重なり解消の構造改善**: 再生時間とハート・Spotifyボタンを同一の末尾グループ（`track-meta-right`）として独立レイアウト化し、画面幅に関わらず重ならない構造にします。
- **歌詞の1発取得**: Spotify SDKの再生同期待ちを不要にし、曲の選択直後から正確なアルバム名・曲名・アーティスト名・再生時間を抽出して即時リクエストします。

## 提案する変更内容

### 1. 曲リスト行の「時間」「ハート」「Spotifyボタン」の重なり完全解消
- **現状の原因**: 
  - `.track-info` が曲名・アーティスト・アルバム・時間を内部グリッドとして保持しており、コンテナ幅が狭くなると時間列が右端の `.track-actions`（ハートとSpotifyボタン）の下に押し出され重なっていた。
- **改善策**:
  - `createTrackCard` のHTML構造およびCSSを改修。
  - 時間表示（`track-col-duration`）とアクション群（`favorite-button`, `spotify-button`）を、右端の独立した `flex-shrink: 0` なグループ（`.track-end-group` または `.track-meta-right`）にまとめ、`gap: 12px` で横並び配置。
  - タイトルとアルバム/アーティスト情報には `min-width: 0; flex: 1; overflow: hidden; text-overflow: ellipsis;` を徹底し、狭い画面でも時間やボタンを圧迫・重なりさせない。

### 2. 歌詞（Lyrics）取得の動作改善（1回で確実に表示）
- **現状の原因**:
  - `loadLyrics()` 内で `track?.album?.name` および `track?.duration_ms` の厳密な存在チェックを行っていたため、プレイリストやお気に入りから曲を再生した直後はオブジェクト形式の差（`albumName` や `durationMs`）によって「曲情報が不足しています」と誤判定され、Spotify SDKが数秒後に詳細を発行するまで歌詞取得が始まらなかった。
  - サーバー側の `/api/lyrics` において、わずかな曲長誤差（±2秒以内制限）やアルバム名の表記揺れでヒットしないケースがあった。
- **改善策**:
  - `public/script.js`: `normalizeTrack` の正規化ロジックを活用し、`track.albumName || track.album?.name`、`track.durationMs || track.duration_ms` を正しく解決して再生開始と同時に即座に歌詞リクエストを開始。
  - `server.js`: アルバム名が完全一致しない場合でも LRCLIB の search API を利用し、曲名・アーティスト名・曲長（許容範囲を柔軟に評価）で1回のリクエスト内で高精度に歌詞を解決して返却。

### 3. アーティスト詳細ページのTop Songs（最初5曲 → ＞ボタンで20曲トグル表示）
- **現状**:
  - `/api/artist-info` は最大10曲を返し、画面には5曲または10曲が固定で表示されていた。
- **改善策**:
  - `server.js`: `/api/artist-info` において Spotify の Top Tracks（10曲）に加え、アーティストのカタログ検索から人気楽曲を補完して **20曲** を返却するように拡張。
  - `public/script.js`:
    - 初期表示状態は **5曲** を表示。
    - `Top Songs` のヘッダー横にある `>`（`.group-arrow`）およびヘッダー行をクリック可能にし、押すたびに **5曲 ⇄ 20曲** を切り替え（矢印も `›` と `‹` または `∨` に連動）。
    - 20曲表示時も、各行をクリックして即座に再生可能。
